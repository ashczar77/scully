## Objective

Verify that the initial Python scaffold provides fail-closed configuration,
redacted measurements, and repeatable offline tests before provider adapters
are implemented.

## Scope completed

- Added Python package metadata and a `src` package layout.
- Added an empty provider namespace without provider implementations.
- Added environment-only configuration with live execution disabled by default.
- Added conservative per-probe budgets and provider-specific credential checks.
- Added secret wrappers whose string representations stay redacted.
- Added bounded measurement records that exclude request and response content.
- Added standard-library offline tests and ignored generated Python artifacts.

## Tests and validations

- `PYTHONPATH=src python3 -m unittest discover -s tests -v`
- Fifteen offline tests passed.
- No provider package was imported or installed.
- No network, model, Tavily API, or Sandbox operation was used.
- Public changes were checked for invalid whitespace, prohibited punctuation,
  credential values, account identifiers, and prohibited attribution.

## Decisions and tradeoffs

- Standard-library `unittest` avoids introducing test dependencies at this
  checkpoint.
- Environment variables are consumed from the process environment. The package
  does not silently read local files.
- `NEBIUS_PROJECT_ID` is canonical, with `CONTREE_PROJECT` accepted for current
  CLI compatibility. Conflicting values fail closed.
- Measurements use an allowlisted schema rather than accepting arbitrary
  metadata that could contain prompts, responses, or credentials.
