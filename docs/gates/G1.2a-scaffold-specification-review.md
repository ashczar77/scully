## Decisions and tradeoffs

- Use Python for the feasibility harness because the official Sandbox examples
  and SDK path are Python-native.
- Keep provider-specific details behind project-owned modules.
- Use standard-library offline tests for the first increment to avoid installing
  provider dependencies before their review.
- Require another review after the offline scaffold before provider code begins.
