## Offline diagnosis

The cancellation path starts only after the timeout path returns a complete,
valid observation. The timeout behavior is therefore proven within the fixed
test boundary.

After the second operation was confirmed, the probe read an active state,
sent the primary cancellation, and observed a terminal response. Because no
cleanup request was recorded, the exception arose during validation of that
terminal response, not while waiting for termination. The retained error type
does not reveal which safe invariant failed. The possible causes are:

1. terminal status other than `CANCELLED`;
2. disposable or result-image retention mismatch;
3. malformed or invalid duration.

The redaction protected provider details but removed one level of diagnostic
information needed to distinguish these cases. Non-sensitive reason codes can
solve that problem without retaining raw provider content.
