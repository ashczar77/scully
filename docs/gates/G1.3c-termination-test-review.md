## Acceptance criteria and evidence

| Criterion | Evidence | Result |
|---|---|---|
| Commands and image are fixed | Two direct `/usr/bin/sleep` calls on `python:3.12-slim`, without shell mode | Pass |
| Remote work is bounded | One-second timeout command and 30-second cancellable command | Pass |
| Creation is bounded | Exactly two disposable spawn calls, with the second gated on the first path | Pass |
| Status verification is bounded | At most ten exact-ID reads per path, 0.5-second intervals, 15-second path deadline | Pass |
| Explicit cancellation is narrow | One primary cancellation addresses only the captured operation ID | Pass |
| Cleanup is bounded | At most one exact-ID cleanup cancellation; no list or cancel-all path exists | Pass |
| Retry behavior is bounded | Retry policy permits one attempt; one stale idempotent-connection resend remains bounded and disclosed | Pass |
| Residual work is bounded | Failed cancellation can leave only the fixed sleep, with a 30-second remote command timeout | Pass |
| State is not retained | Both results must report disposable mode and no result image | Pass |
| Termination cannot prove reproduction | Timeout and cancellation must both evaluate as `inconclusive` | Pass |
| Durable evidence is redacted | Operation IDs, output, provider messages, credentials, and project ID are excluded | Pass |
| Live gate remains closed by default | Exact package, credentials, provider target, two-operation cap, and 15-second setting are all required | Pass |

## Decisions and tradeoffs

Polling is used instead of the client's event-following waiter. Polling costs
more read calls, but it gives the review a fixed application-call ceiling and
does not rely on a variable number of event-stream reconnections.

The provider's operation duration is retained when available. The direct
client does not report the earlier Sandbox cost field, so the result records
that provider-reported cost is unavailable rather than interpreting a missing
value as zero.

The test uses disposable operations to resolve new retention for these paths.
The retention policy for the three earlier untagged states remains a G1.4
follow-up.
