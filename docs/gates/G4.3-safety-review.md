# Gate G4.3: Safety Review

**Status:** Ready for review

**Review date:** 2026-09-12

**Decision:** Approved

**Decision owner:** Project owner

## Scope reviewed

Gate G4.2 authorized Step 4.3 only. This review covers capsule and prompt
boundaries, sensitive-content checks, command and experiment policy, export
validation, resource limits, terminal failure handling, recovery behavior,
audit event schemas, and insufficient or inconclusive evidence handling.

It does not authorize Step 4.4 reliability work, provider execution,
deployment, expanded incident support, or submission publishing.

## Safety decision table

| Criterion | Evidence | Result |
|---|---|---|
| Adversarial capsule inputs fail closed | Absolute, Windows, parent, duplicate, symlink, null, malformed, mismatched, undeclared, oversized, and sensitive inputs are covered | Pass |
| Prompt injection cannot select execution | Incident text is delimited as untrusted JSON; only exact application-owned variants and parameters pass validation | Pass |
| Sensitive planner output is stopped | Accepted structured output is rescanned before hypotheses can be persisted | Pass |
| Command policy remains fixed | Local execution invokes Node directly without a shell; Sandbox commands remain application-owned constants | Pass |
| Export is rescanned | Every source file and generated manifest passes UTF-8, null-byte, and sensitive-content checks before archive creation | Pass |
| Export paths and size remain bounded | Exact file allowlist, symlink rejection, one fixed package root, and 2 MiB limits are enforced | Pass |
| Audit records are bounded | Event types and payload keys are allowlisted, payloads are capped at 4 KiB, and sequences remain contiguous | Pass |
| Provenance and redaction are auditable | A content-free evidence-boundary event records evidence, provenance, clean, redacted, and scan counts | Pass |
| Unsafe failures are terminal | Known and unexpected execution errors persist redacted failure events and close the investigation | Pass |
| Failure detail is not leaked | Only bounded reason codes enter events; provider or exception detail is neither persisted nor returned by the service | Pass |
| Retry and recovery are explicit | Automatic retries remain zero; a terminal run cannot be rerun, and the interface creates a fresh investigation after correction | Pass |
| Resource ceilings remain enforced | Branch operations, local and provider timeouts, command output, event payload, and archive size are bounded | Pass |
| Insufficient evidence is explicit | Missing known-good comparisons return `insufficient_evidence` and block the browser action | Pass |
| Inconclusive results do not become proof | No single supported cause means no proof view and no reproduction package | Pass |
| Provider boundary remains closed | No provider client, request, credit, cost, cancellation attempt, or control was introduced | Pass |

## Known limitations

1. Sensitive-content matching is bounded pattern detection, not full semantic
   data-loss prevention.
2. Explicit remote cancellation remains known technical debt. Provider timeout
   plus local deadlines remains the approved fallback.
3. Terminal recovery creates a fresh investigation rather than resuming state.
4. Clean-checkout and sponsor-stack repeatability remain Step 4.4 work.
5. Direct target-engineer validation and previously recorded provider debt
   remain open.

## Recommendation

Approve Gate G4.3 and authorize Step 4.4 only: prove repeated local and sponsor
stack behavior, clean-checkout setup, measured latency and credit use, and
documented recovery without changing the accepted feature scope. Any live
provider run remains subject to its own reviewed preflight, exact request
budget, and cost check.
