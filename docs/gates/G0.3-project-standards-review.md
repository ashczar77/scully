## Alternatives and trade-offs

### Keep standards only as general guidance

This is simpler, but it makes gates subjective and does not establish when
automation is required.

### Automate every rule immediately

This would delay product research and force tool choices before the repository
and build architecture are approved.

### Selected approach

Define enforceable requirements now, use manual evidence initially, and add
automation at the phase where the relevant technical foundation exists.
