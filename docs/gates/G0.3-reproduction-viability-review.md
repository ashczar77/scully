## Objective

Attempt clean manual reproduction of all three approved candidate incidents,
record the exact source, versions, commands, signatures, known-good results,
missing evidence, and failed attempts, then determine whether at least two
incidents are viable from safe capsules.

## Scope completed

- Built original minimal fixtures for Node.js, Python, and JVM incidents.
- Pinned the runtime and dependency versions used by each comparison.
- Ran each incident configuration in three clean temporary environments.
- Ran each known-good configuration in three clean temporary environments.
- Evaluated process, HTTP, identity, exception, and output signatures with
  deterministic checks.
- Recorded failed setup attempts, adjustments, evidence gaps, and limitations.
- Added a normalized machine-readable result summary.

## Tests and validations

- Proxy incident: 3 of 3 clean runs matched `200,429` with one normalized
  identity.
- Proxy known-good: 3 of 3 clean runs produced `200,200` with distinct
  identities.
- Pydantic incident: 3 of 3 clean environments exited with the required
  `PydanticImportError` tokens.
- Pydantic known-good: 3 of 3 clean environments exited successfully with the
  ready result.
- Jackson incident: 3 of 3 clean builds exited with `NoSuchMethodError` for
  `BufferRecycler.releaseToPool()`.
- Jackson known-good: 3 of 3 clean builds serialized the ready result and
  exited successfully.
- Confirmed the normalized JSON result reports three attempted, three
  reproduced, and a met threshold of two.
- Checked changed public files for invalid whitespace and prohibited
  punctuation.

## Decisions and tradeoffs

- Unique temporary directories and Python virtual environments satisfy this
  manual gate's clean-run requirement. Docker was not required because its
  daemon was unavailable.
- Shared package-manager caches were permitted for public artifact acquisition.
  Installed dependencies, build output, and process state remained isolated.
- The Pydantic fixture uses a startup-ready output rather than an HTTP server.
  An API framework would not change the import failure evidence.
- The Jackson fixture uses a direct serialization probe rather than an HTTP
  endpoint. This keeps the version-skew evidence compact and exact.
- These simplifications support manual validation but may make the Pydantic and
  Jackson cases less suitable for the final visual demonstration.
