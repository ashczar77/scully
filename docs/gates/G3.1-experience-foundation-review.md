# Gate G3.1: Experience Foundation Review

**Status:** In review

**Review date:** 2026-09-11

**Decision:** Pending project-owner review

**Decision owner:** Project owner

## Scope reviewed

Gate G2.5 authorized Step 3.1 only. This review covers the five-screen
information architecture, primary and exceptional investigation flows, visual
tokens, semantic evidence states, responsive behavior, keyboard requirements,
focus behavior, contrast requirements, and reduced-motion behavior.

It does not cover implementation of the five screens. That work begins at Step
3.2 only after this gate is approved.

## Evidence

| Criterion | Evidence | Result |
|---|---|---|
| Every screen answers an engineering question | Five-screen table binds each route to one question, required answer, and primary action | Pass |
| Navigation matches investigation state | Linear flow covers intake, overview, map, inspector, and proof with explicit exceptional exits | Pass |
| Evidence states are semantically distinct | Every state has a text label, symbol, structure, and supporting color | Pass |
| State survives monochrome presentation | Labels, symbols, rails, and elimination reasons remain without color | Pass |
| Observation and inference remain separate | Observed evidence and untested hypotheses use distinct language and structure | Pass |
| Reproduction and hypothesis support remain separate | Foundation explicitly prevents a reproduced branch from being mislabeled as supported | Pass |
| Primary flow does not depend on motion | Motion never blocks actions and reduced motion preserves all state information | Pass |
| Contrast has an implementation threshold | Body and state text target at least 4.5:1, non-text boundaries at least 3:1 | Pass |
| Keyboard behavior is explicit | Focus order, skip link, target size, current item, dialogs, tables, and diffs are defined | Pass |
| Exceptional states are useful | Failed and inconclusive flows preserve evidence and offer distinct next actions | Pass |
| Responsive behavior preserves meaning | Desktop rail becomes named progress, graph becomes ordered list, and diffs stack | Pass |
| Provider authority is unchanged | Foundation introduces no live-provider controls or execution path | Pass |

## Known limitations

1. These foundations are an experience contract, not implemented screens.
2. User comprehension has not been directly tested with target engineers.
3. Exact component contrast must be rechecked against its actual surface during
   implementation.
4. Pause and exclude actions remain unavailable until supported by application
   behavior. The foundation forbids presenting inert versions.
5. Live provider limitations and explicit cancellation debt remain unchanged.

## Recommendation

Approve Gate G3.1 and authorize Step 3.2 only: implement capsule intake and the
incident overview against these foundations, including responsive and
keyboard-accessible states. Keep hypothesis-map, experiment-inspector, proof
experience, and provider changes outside that authorization.
