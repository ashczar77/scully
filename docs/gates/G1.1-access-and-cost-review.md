## Decisions and tradeoffs

- Access setup and live capability execution are separated. Read-only checks
  close G1.1, while bounded live probes become Step 1.2 project code.
- This avoids disposable manual experiments and makes the first infrastructure
  work produce reusable measurements and provider boundaries.
- Python is proposed only for the Phase 1 feasibility harness because the
  official ConTree SDK is Python-native. This does not decide the later web or
  product stack.
- The zero-spend policy takes precedence over completing a probe. Missing price,
  usage, balance, or limit data causes the run to stop.
