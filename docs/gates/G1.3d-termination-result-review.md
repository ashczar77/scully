## Root cause and corrective boundary

The pinned API schema defines an image source as a UUID or a string beginning
with `tag:`. The higher-level SDK accepted `python:3.12-slim` in earlier
probes, but the direct client sent that string without normalization. The
provider rejected the request with HTTP 400 and returned no operation ID.

A corrective offline checkpoint should be limited to:

1. changing the direct image source to `tag:python:3.12-slim`;
2. adding an adapter-level image-source validator that runs before a request;
3. separating spawn calls attempted from operation IDs confirmed;
4. testing both allowed image-source forms and rejecting unprefixed tags;
5. rerunning the complete offline suite;
6. submitting a new execution proposal for review.

No second live attempt is authorized by this review request.
