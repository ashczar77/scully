## Objective

Assemble three candidate incident capsules with explicit provenance,
sensitivity, redaction, rights, failure signatures, known-good comparisons,
and expected environment deltas.

## Review history

The project owner requested revision of the original submission before a gate
decision. The original candidate set was overconstrained to JavaScript,
TypeScript, and Node.js. That choice prematurely mixed Scully's possible
implementation stack with the applications it may investigate.

The revision conditions were:

- define capsules independently of programming language;
- select incidents by problem quality and evidence availability;
- cover at least two application ecosystems;
- prefer a real, safely reconstructable incident pattern where available;
- use synthetic cases only where they provide a useful safety boundary;
- defer Scully's implementation stack decision to Gate G1.4.

The revised submission satisfies these conditions and returns G0.2 to project
owner review.

## Scope completed

- Defined a technology-neutral capsule and candidate-selection rules.
- Selected Node.js, Python, and JVM cases covering deployment topology,
  dependency migration, and runtime classpath skew.
- Grounded every synthetic reconstruction in primary technical documentation

- Defined a draft capsule, machine-readable target signature, and known-good

- Inventoried every planned artifact by provenance, sensitivity, redaction,

- Kept Scully's own implementation language and framework undecided.

## Tests and validations

- Verified the proxy case against the Express trusted-proxy documentation.
- Verified the Python case against the Pydantic migration guide and a public

- Verified the JVM case against Spring Boot dependency-management guidance and

- Confirmed no generated fixture log, package lockfile, runtime artifact, or

## Decisions and tradeoffs

- The capsule contract is technology-neutral. Individual capsules retain exact
  ecosystem metadata because reproduction depends on it.
- Ecosystem diversity is a validation control, not a promise that the first
  release will support every language.
- Synthetic reconstructions keep privacy and rights unambiguous. Public issue
  records establish that the underlying failure patterns occur in real systems.
- The proxy case remains first because it combines request evidence, deployment
  topology, and configuration while producing a functional failure.
- The Pydantic case provides a compact second ecosystem and a strong startup
  signature, but it may be too obvious for the final demonstration.
- The Jackson case exercises a more complex dependency graph and request-time
  failure, but exact version selection may require more setup.

## Recommendation

**Approved.** The revised set tests a technology-neutral capsule across three
ecosystems without production credentials, customer data, secrets, copied
application code, or unclear rights. Approval should authorize manual fixture
construction and reproduction attempts in Step 0.3. It should not be
interpreted as evidence that any candidate is reproducible or valuable to
target engineers.
