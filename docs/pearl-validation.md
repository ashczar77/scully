## Reviewed multi-file edit increment, 23 October 2026

Pearl can propose one `edit_files` action for two to eight files. The Room presents the full proposed diff for a one-use decision. The privileged backend checks project approval, relative paths, private-path and symlink boundaries, duplicate paths, the SHA-256 revision of every existing file, and the exact reviewed contents. Approval rechecks those facts before staging. Existing originals are backed up, failed promotions roll back earlier files, and a private journal lets startup recovery roll back a batch interrupted before its committed marker. A conflicting external edit is left untouched and reported for inspection. The combined before/after content limit is 400,000 characters. Single-file tools still work separately.

## Public web search increment, 22 October 2026

Pearl can optionally search public web sources and read a result from the same user turn after a Tavily key is entered in Settings. The key stays in backend memory for the app session. Searches are limited to 12 provider attempts per turn, return up to five HTTPS results, and have a 12-second provider timeout. Repeating an identical successful query reuses its result without another provider request or search slot. Reading is limited to 20 returned results per turn. The backend rejects private targets and obvious paths or credentials in queries, and bounds provider responses before saving observations. Search and read counts, including failed attempts, are restored from saved chat observations after an interrupted turn. Source text remains untrusted and cannot grant project or command access. The Room shows the actions in Activity and prompts Pearl to cite source URLs.

The default suite passed 204 tests after the required local loopback permission was granted. Typecheck, build, formatting, the full Electron desktop gate, macOS package, and packaged smoke passed. The new desktop fixture covered an ordinary chat without project access, search and reading through the actual backend, a cited Room reply, and restored history after restart. A direct Tavily check returned official TypeScript search results and extracted a public page. The final connected Room check used `zai-org/GLM-5.3-Flash`: three model requests, one search, one page read, and a cited answer supported by the extracted section. Its ignored local record is `test-results/pearl-web-live-1792678721452.json`.

An earlier connected check cited Microsoft's official announcement, but its script incorrectly accepted only a `typescriptlang.org` URL. That assertion was corrected to require a URL returned by the actual search. The same review found that generic extraction used much of its content limit on site navigation. Query-focused extraction returned the relevant section in about 2,140 characters in the final connected run. These checks establish this bounded public-search journey, not the accuracy of every future search or model answer. The query filter is a safeguard, not a guarantee that a model cannot put sensitive context into a search term. Tavily receives search queries and selected result URLs; users should review that data flow before connecting a key.

## Runtime changes and diagnostic history

The runtime now supports reviewed local application servers and persistent isolated browser sessions. Subsequent browser actions retain cookies, storage and page state. Source edits invalidate a preview so a server running old code cannot count as verification. Visible controls have unique selectors; native Enter submits forms, and arrow keys are translated to the desktop API key names; partial action failures preserve observations of earlier side effects. Stop, project changes and application exit close the preview processes. Desktop fixtures cover these boundaries.

Context retention keeps the latest source observations and compacts superseded file operations without changing stored history. A revisioned working plan keeps user quotes distinct from proposed implementation choices. The configured inexpensive model uses a conservative 320,000-character local context allowance, with a smaller retry allowance. This is a character budget, not an exact tokenizer or the provider's advertised maximum. [Nebius model specifications](https://nebius.com/services/token-factory/models/glm-models-inference) document the model's larger available context.

A provider protocol audit found that the adapter discarded reasoning continuation returned alongside tool calls. The model publisher explicitly requires preserving these blocks for interleaved tool use. The adapter now stores and replays the original continuation within the active user turn to the same model, including across approval and restart, while excluding it from Room IPC and telemetry. Streamed and non-streamed fixtures cover exact preservation, model changes, bounds and persistence. [Model protocol documentation](https://docs.z.ai/guides/capabilities/thinking-mode) explains this requirement. The selected model uses explicit high reasoning effort rather than its default maximum, with the publisher-recommended sampling parameters. [The model card](https://huggingface.co/zai-org/GLM-5.3-Flash) documents the reasoning levels. These corrections do not, by themselves, prove task quality.

A diagnostic expense-tracker run produced 41 passing generated tests but repeated browser work. It was stopped and preserved after exposing browser-session and selector defects. A continuation exposed premature source eviction during context trimming. A later continuation repaired a budget-save confirmation defect found by independent browser testing, then encountered HTTP 429 before completing its own checks. Independent browser checks passed household creation, Enter submission, reload persistence, keyboard editing, budget confirmation, member invitation, shared entry visibility and rejection of reused invitations. Those observations were partial evidence; the subsequent completed journeys are recorded above. A subsequent inventory diagnostic stopped after implementing only its storage layer. The task-continuation instructions were clarified, and the harness now rejects an unfinished implementation before browser acceptance.

Remaining limits include character-based context accounting, bounded preview lifetimes, platform-specific command confinement and lack of evidence for broad package-installation or deployment workflows. These limits must not be presented as parity with an unrestricted development environment.

The completion tool's `remaining` field must be omitted for `done`. A live run supplied a sentence saying nothing remained; vague rejection feedback caused unnecessary additional work. The schema and rejection now describe the field conflict precisely rather than suggesting that the backend discovered an omitted feature. Plan revision errors similarly return the actual current revision. These are protocol corrections, not prompt-specific response rules.

A live keyboard check exposed a browser-tool defect: DOM names such as `ArrowDown` were passed directly as native key codes, producing an empty page event key. A minimal Electron fixture reproduced the mismatch independently of generated application code. The mapping now follows the [desktop keyboard API](https://www.electronjs.org/docs/latest/api/structures/keyboard-input-event) and [supported key codes](https://www.electronjs.org/docs/latest/tutorial/keyboard-shortcuts#available-key-codes). The desktop gate asserts all four arrows, Escape, Tab, Backspace, Enter and punctuation against actual page events.

The command confinement review also found that a system executable such as `/bin/sh` could expand the runtime-library read allowance to the filesystem root. The allowance is now narrowed when an installation parent contains the home directory or filesystem root. A real process regression verifies that a shell cannot read the same synthetic outside-project file that Node is denied. This correction does not remove the documented access to project files, local services and ordinary system resources.

A completion-boundary review reproduced two stale-evidence failures: a JavaScript or server edit could leave a prior browser result valid, and passing commands could mask a failed browser-only verification turn. Both now have regressions. Any later write invalidates browser evidence; once browser verification is part of a turn, it must succeed before `done` is accepted. File-extension classification still cannot discover every UI dependency, so independent behavior checks remain necessary.
