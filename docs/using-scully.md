# Using Scully

Scully opens a Room chat with Pearl. Pearl can answer ordinary questions, discuss requirements, plan, and use project tools in the same conversation. The current interface is Pearl-only. Team workflows and old task history are preserved as legacy implementation, not displayed in the Room.

## Connect a model

Open the full-page **Settings** view, choose a primary model on **Models**, then enter a Nebius Token Factory API key under **App & connection**. New connections suggest `Qwen/Qwen3-235B-A22B-Instruct-2507`; you can choose another model before connecting. Once connected, Settings lists the models returned for that Nebius account. Switch the primary model on the Models tab without re-entering the key. The new choice applies to new turns; a turn already running keeps its current model. A model listing does not guarantee that a model responds quickly or uses coding tools well. The key remains in memory for this app session and is needed again after restart. Do not paste keys into chat or project files. A provider connection failure keeps the user's message and completed actions. Check the reported cause, then select **Continue** after the connection is restored. A model request that does not finish within 90 seconds ends with a timeout error; Continue starts a fresh request using saved context.

If your selected model is slow or unavailable, you can explicitly enable a second Nebius model in **Settings**. This choice is off by default and must be made again after restart. Pearl uses the second model when the selected model fails to start responding within 25 seconds, loses its connection, is rate limited, returns a service error, or times out before an action is accepted. After a switch, later steps in that user turn stay on the fallback, including after an approval or restart if you reconnect with the same fallback enabled. The next user message starts with the selected primary model again. A rejected API key does not trigger a fallback. The Room labels replies and activity produced by the fallback model. Both models use the same Nebius key, and each request may incur model usage.

## Start a chat

Choose **New chat**, then ask Pearl a question or describe work. Chats are saved in local SQLite storage and appear in the sidebar. Pearl may answer directly, propose a project action, or ask a linked product question. A linked answer is attached to that exact question. The composer stays available while a question is pending, so you can ask about alternatives or change the subject.

A new requirement can change an earlier recommendation. Check that Pearl acknowledges the correction before relying on a plan or code change. The [validation status](pearl-validation.md) records the observed quality checks and their limits.

## Search the public web

Web search is optional. In **Settings**, open **App & connection** and enter a Tavily API key to let Pearl search current public information and read a page returned by that search. The key stays in memory for this app session. Pearl may send short queries and selected public result URLs to Tavily; the returned results are saved in the chat. Disconnect in Settings to stop further searches. Do not put credentials or private project content in a search request.

Search is available without project approval. Each user turn permits at most 12 provider search attempts and 20 reads. Repeating an identical successful query reuses its result without another provider request or search slot. A read can open only a public HTTPS result from the current turn, and the returned content is bounded and may be truncated. Pearl should cite the source URL for information it uses. Web pages are treated as untrusted content and cannot grant project or command permissions.

## Connect a remote MCP server

Open **Settings**, then **App & connection**. Enter one public HTTPS Streamable HTTP endpoint and, if required, a bearer token. The connection and token last only until Scully closes. Settings shows the discovered tool names. Ask Pearl to use a tool; the Room will show the endpoint, tool name, and exact arguments before anything is sent. Choose **Call once** or **Deny**. The server can change external data regardless of its tool description. Approved call arguments go to the server; discovered tool details and results enter Pearl's chat context through Nebius. Replacing or disconnecting the server invalidates an approval that has not been used. OAuth login and multiple concurrent MCP connections are not supported yet.

## Work in a project

Choose a local project folder from the Room header. Scully shows the exact folder and asks for approval before Pearl may read or edit its files. The approval is scoped to that folder for this chat. Pearl's file tools use relative paths, reject private paths and symlinks, and limit file size. Existing files require the SHA-256 revision returned by a prior read. If a file changed after Pearl read it, the edit is rejected and Pearl must inspect it again. Scully retains the original content of existing files in local backups before a write.

Pearl can propose a command. The Room shows its arguments and resolved executable, and the backend accepts one approval for that pending command only. Choose **Run once** or **Deny**. Commands run in the project under your local account with a time and output limit. On macOS, a system policy limits writes to the project, restricts reads from private directories, and blocks remote networking. Project files and local loopback services remain accessible. Other platforms currently reject execution. A command exit code is an observation, not proof that a feature works. Review project scripts before running package-manager commands. After file changes, Pearl must report a completion status tied to recorded edits and checks. Read the [runtime design](pearl-runtime.md) for the exact limits of that evidence.

For a process that needs to keep running, Pearl can request a managed terminal. Review and approve its exact command once. Its recent output appears in the chat; you can type input into that session or stop it there. Pearl may read the output or stop the process, but only you can type into it. Input you type into an approved shell can start further commands within the project sandbox. At most eight terminals run in one chat and sixteen across the app. An attended terminal has no fixed lifetime; it ends when stopped or the app exits. Stop a running terminal before archiving its chat or changing projects. Terminal sessions do not resume after an app restart. The interactive terminal supports keyboard controls and full-screen programs, and resizes with the Room. Only the recent output tail is saved, so reopening a collapsed terminal may not reconstruct an earlier full-screen display.

For a static web page in the approved project, Pearl can use `browser_check` to load an HTML entry, inspect visible text and controls, and perform a short sequence of click, fill, key, or reload actions. The browser blocks external requests, private project paths, and permissions. For a backend-driven app, Pearl requests separate approval to start the exact local server command. The server receives HOST and PORT settings, and an isolated browser retains cookies and page state across interactions. The preview ends on completion, source edits, Stop, or its ten-minute limit. Browser actions can change application data. Only the allocated local origin is accessible; this project browser does not open arbitrary external sites. These observations do not prove every user journey. After an HTML, style or component edit, the backend requires a clean browser observation as well as a successful command check before accepting `done`. Once browser verification is used, later file edits invalidate that result, and passing command tests cannot hide a failed browser check.

## Stop and recover

**Stop** cancels a current model request or command when possible. A command may already have made partial changes, so inspect the project before retrying. An app restart preserves chat and question state. An action whose result was not recorded is marked unknown rather than silently repeated. **Continue** resumes from the saved conversation after an interruption or work budget pause. The model connection must be re-entered after restart.

## Verification status

`npm test`, `npm run typecheck`, `npm run build`, `npm run format:check`, `npm run test:desktop`, and the package checks are separate gates. The desktop fixture runs a Room journey through a local model HTTP endpoint and disposable project. It verifies wiring, persistence, and permission boundaries. It does not measure Pearl's reasoning or tone. The opt-in `npm run test:live:pearl` exercises the configured provider and saves a local transcript for human review. The recorded live journeys include varied wording, changed requirements, implementation, browser-discovered repairs and recovery. Their results apply to the tested local application workflows. See [validation status](pearl-validation.md) for the current scope and evidence map.
